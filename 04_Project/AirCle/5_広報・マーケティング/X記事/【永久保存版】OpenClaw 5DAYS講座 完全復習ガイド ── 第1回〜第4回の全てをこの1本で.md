# 第1回：「もう一人の自分」神運用メソッド

**2月27日（金）20:00〜22:00 ── 1,000人満席**

### 5DAYS講座の原点

5DAYS講座は、ここから始まった。テーマは**「OpenClaw × GitHub × Obsidian」で実現する「もう一人の自分」神運用メソッド**。

ManusやNotion AIなど既存ツールで満足している「指示待ちAI」から、寝ている間も勝手に働き続ける「もう一人の自分（パートナー）」へ。その転換点になる回。

### AIを使いこなせない原因

AIに指示を出すたびに「背景」や「文脈」をゼロから説明していないだろうか。それは、AIを「優秀な派遣社員」としてしか使えていない状態。

OpenClawを使いこなせない原因は**「情報の一元管理（コンテキストの設計）」ができていないこと**にある。メモはNotionに、仕事の記録はGoogleドキュメントに、アイデアはスマホのメモアプリに──こんな状態では、OpenClawは力を発揮できない。

**文脈（コンテキスト）こそが最強の資産。** これが複利のように積み重なる仕組みを作ること。ここが第1回の核心だった。

### 神運用メソッド：Obsidian × GitHub × OpenClaw

第1回で初公開した**「神運用メソッド」**は、3つのツールの組み合わせ。

**Obsidian（冷蔵庫）** ── 知識をストックする無料のメモアプリ。

読んだ本の感想、仕事で学んだこと、アイデア、成功・失敗の記録。全部ここに.md（Markdown）で貯める。

**GitHub（キッチン）** ── 情報を整理・管理する場所。

GitHub Actionsという「自動で動くお仕事ロボット」を使えば、Gmail、Googleカレンダー、Xのデータを自動で集めてこれる。プログラミング不要。レシピ（テンプレート）を使うだけ。

**OpenClaw（スーパーシェフ）** ── 冷蔵庫から食材を取り出し、キッチンで整理された情報を見ながら、最高の仕事をする。

**冷蔵庫の中身が豊かで整理されているほど、シェフの料理の質が上がる。**

### デモでやったこと

- 朝起きたらタスクが完了している「Telegram通知」
- 3時間後の会議資料をAIが先回りして作成
- 過去のバズった投稿を分析し、毎朝60個の投稿案を自動生成

1,000人の前で「もう一人の自分」の世界を見せた回。

### なぜ.md（Markdown）なのか

- AIは**テキスト**を読むのが得意
- WordやExcelより**AIにそのまま渡しやすい**
- **差分管理（Git）しやすい**
- **どこでも開ける**

Obsidianの中身は.md。.mdで一元管理している人がAI時代に圧倒的に有利になる。

### 第1回のまとめ

- **OpenClawは「もう一人の自分」を作れるAIエージェント**
- **神運用メソッド = Obsidian（冷蔵庫）× GitHub（キッチン）× OpenClaw（シェフ）**
- **情報の一元管理がOpenClaw活用の全ての土台**
- **コンテキスト（文脈）が複利のように積み重なる**
- **エンジニアじゃなくても、半日〜1日で構築できる**

# 第2回：OpenClaw超入門 ── 「結局、何がすごいの？」を完全に終わらせる

**3月8日（日）20:00〜22:00 ── ★ 初めての方はここから視聴推奨**

### 「全員理解させる」回

第1回のあと、参加者から一番多かった声が「面白かったけど、正直ちょっと難しかった」だった。だから第2回は**「全員理解させる」回**にした。

コンセプトはシンプル。**「OpenClawを小学生でもわかるレベルで解説し、セキュリティの不安も解消する」超入門回。**

### ChatGPTの「限界」

まず、ChatGPTの限界から。

**あなた**「明日のプレゼンの構成を考えて」
**ChatGPT**「はい！こんな構成はいかがでしょうか。」

──で、スライド作るのは誰？ **自分。**

「カレンダーに予定を入れて」って頼んでも、入れてくれない。**カレンダーを操作する「手」がないから。**

ChatGPTは**めちゃくちゃ頭のいい友達**。教えてくれるけど、**やってはくれない。**

### AIエージェントの登場

この限界に世界中が気づいて生まれたのが「AIエージェント」── **自分で手を動かしてくれるAI**。

Manus、Devin、Notion AI……いろいろ出てきた。でも全部に共通する弱点が2つある。

**弱点1：頼まないと動かない。** 「これやって」って言わない限り、ずっとボーッとしてる。

**弱点2：あなたのことを覚えていない。** 毎回「私はこういう仕事をしていて…」と説明し直す必要がある。

人間で言えば、**「すごく優秀だけど、言われないと何もしない、しかも毎回初対面の新入社員」**。

### OpenClawの3つの決定的な違い

第2回の核心メッセージはこれ。

**ChatGPTは「教えてくれるAI」、AIエージェントは「やってくれるAI」、OpenClawは「勝手にやっておいてくれるAI」。**

**違い①：頼んでないのに、勝手にやっておいてくれる（自律性）**

- 朝、寝ている間にメールを整理しておく
- 3時間後の会議を察知して、資料のたたき台を勝手に作る
- Xの投稿案を60個用意しておく

**違い②：あなたのことを、ずっと覚えている（永続メモリ）**

- 「出張はグリーン車」→ 覚えてる。次から聞かずに手配
- 「文章は柔らかいトーン」→ 覚えてる。ずっとそのトーンで書く
- 使えば使うほど、あなた専用のAIに育っていく

**違い③：無料。しかもデータは自分のパソコンの中（ローカル）**

| | ChatGPT | 他のAIエージェント | OpenClaw |
| --- | --- | --- | --- |
| 例えると | 頭のいい友達 | 優秀な新入社員 | **10年来の最高の相棒** |
| やってくれる？ | 教えるだけ | 頼めばやる | **頼まなくても勝手にやる** |
| 覚えてる？ | 忘れる | 忘れる | **ずっと覚えてる** |
| 寝てる間に働く？ | 無理 | 無理 | **働いてくれる** |
| いくら？ | 無料〜月3,000円 | 月3,000〜30,000円 | **無料**（API代のみ） |
| データはどこ？ | クラウド | クラウド | **自分のPC** |

### セキュリティの正しい理解

第2回の後半はセキュリティの深掘り。

**「怖い」の正体**

- ブラウザクッキー・保存されたログイン情報が盗まれるリスク
- ClawJacked脆弱性（悪意あるWebサイト経由の乗っ取り）
- マーケットプレースの危険なプラグイン
- 「事業内容が盗まれる」レベルではなく**「お金が盗まれる」レベル**の話

**安全に始めるための3段階対策**

1. **最低限**：専用のMac mini等で個人情報ゼロの環境を作る
2. **推奨**：ネットワークを仮想化し、メインPCと隔離する
3. **理想**：物理的に別ネットワークに置く
4. **承認フロー**：重要な操作はDiscord等で別経路の承認を求める

**「怖がってやらない」が一番もったいない。正しく怖がって、正しく始める。**

「わからないから怖い」を「わかったから安心して始められる」に変える。それが第2回の役割だった。

### 第2回のまとめ

- **ChatGPT = 教えてくれるAI。OpenClaw = 勝手にやっておいてくれるAI**
- **OpenClawの3つの強み：自律性・永続メモリ・無料＋ローカル**
- **セキュリティは正しく対策すれば怖くない**
- **「情報の一元管理」がOpenClaw活用の核心**

# 第3回：OpenClaw × X運用 ── AIでフォロワーを爆伸ばす実践講座

**3月18日（水）22:00〜23:20（80分）**

### OpenClawの「最もわかりやすく、最も即効性のある活用法」

第3回のコンセプトは、**「OpenClaw × X運用」── AIでフォロワーを増やし、売上に繋げる実践回**。

「OpenClawがすごいのはわかった。で、具体的に何に使えばいいの？」に対する一番わかりやすくて即効性のある答えがX運用。個人XアカウントのコンセプトをOpenClaw一本に変更した結果、**1日で300人のフォロワー増加**を達成した。第3回ではそのフローの設計と実践を80分に凝縮した。

### フォロワーが伸びる「公式」

**投稿数 × バズる投稿の型（見やすいか？）× 情報密度（有益さ）**

この3要素が揃ったときだけフォロワーは伸びる。

大事なのは**今どの段階にいるか**で「いちばん効く要素」が変わること。

| グループ | いちばん効く要素 | やること |
| --- | --- | --- |
| **A**（200人以下・投稿まだ少ない） | **投稿数** | まず量を増やす。そのうえで型と情報密度を意識 |
| **B**（200人以上・30投稿くらいしてる） | **バズる型** | 伸びた投稿を分析して型にする。その型で量産 |

### なぜOpenClawでXが伸びるのか

OpenClawは**3要素すべてにレバレッジをかけられる**。だからX運用と相性がいい。

**① 投稿数 → AIが案を量産。しかも「あなたの文体・型」を永続メモリで覚えている。**

ChatGPTでも案は出せる。でも毎回文体を説明し直す必要がある。OpenClawは一度覚えたら、ずっとあなたの文体で書いてくれる。

**② 情報密度 → 最新情報は毎朝自動収集。1次情報はメモリからいつでも出せる。**

| | 最新の情報 | 自分だけの1次情報 |
| --- | --- | --- |
| 他AI | 取れるが毎回手動 | 弱い・毎回入力 |
| OpenClaw | 毎日6時・13時・21時に自動収集 | memory.md に蓄積、いつでも出せる |

1次情報（自分にしか出せない体験・実績・独自の解釈）は差別化の核。浅い情報が溢れる時代で、フォロワーをファンにするのはここ。

**③ バズる投稿の型 → 分析結果をメモリに入れておけば、ずっと覚えていて型で量産できる。**

**バズる型は、アカウントによって違う。** コンセプトとフェーズで変わる。だから「自分のアカウントで何がバズるか」を分析して型にする必要がある。

他AIでも分析はできるけど、毎回結果を入れ直すのがマジで面倒。OpenClawなら永続メモリに置いておけば、ずっと覚えていてくれる。

### 実践：分析 → 1ポストまでやる

**ステップ1：分析データを用意する**
- Xプレミアムあり → 分析結果をそのまま活用
- なし → 参考にしたい投稿を5〜10本リサーチしてスプレッドシートにまとめる

**ステップ2：OpenClawに渡して「1本出して」と依頼**

セミナーでは画面共有でこの流れをリアルタイムでデモした。分析データを渡して、1本の投稿案が出てくるところまで。

### 応用：毎朝60個の投稿案を自動生成

1. **毎朝6時**に、AI系の最新情報を自動で拾う
2. 投稿ソース20個 × バズる型3種類 = **60個の投稿案を自動生成**
3. あとは**選ぶだけ**

ただし注意。**出てきた案をそのまま出すだけでは、毎回バズるほど世の中は甘くない。**

- バズった投稿があればOpenClawに報告する
- 型を更新し続ける
- **OpenClawとの共同作業でPDCAを回し続ける**ことが一番大事

### 最強応用：具体 → 抽象の言語化

バズったXの投稿（具体）→「なぜバズったか？」の言語化（抽象）
集客できた広告バナー（具体）→「なぜ集客できたか？」の言語化（抽象）

これをOpenClawのメモリに貯めておくと、次の施策やコンテンツに使い回せる。だから**OpenClawはX運用だけじゃなく、マーケティング全般と相性がいい**。

X投稿だけじゃない。**メルマガ・LP・ブログ記事・コンテンツ**もOpenClawで量産できる。セミナーの最後にはLP作成のデモもやった。「LPを作って、Vercelでデプロイして」と頼むだけで、数分でURLが出てくる。

### 第3回のまとめ

- **フォロワーが伸びる3要素**：投稿数 × バズる型 × 情報密度
- **OpenClawは3要素すべてにレバレッジをかけられる**
- **分析 → 型化 → 量産をOpenClawで回す**
- **毎朝60個自動生成 → PDCAを回し続ける**
- **具体→抽象の言語化で、マーケ全般に応用できる**

# 第4回：OpenClaw vs Claude Code Channels ── 開発の世界を切り拓く

### 「なぜ非エンジニアにOpenClawが重要なのか？」を120分で証明する回

核心メッセージは3つ。

- **OpenClawはお金稼げる魔法のツールじゃない。** だけど、学ぶことは大きすぎる**「複利」**になる

### Claude Code Channels vs OpenClaw ── 3つの決定的な違い

| | Claude Code Channels | OpenClaw |
| --- | --- | --- |
| **メモリ** | セッション単位（会話が切れると忘れる） | **永続メモリ**（文脈を覚え続ける） |
| **自律性** | 指示に対して応答 | **自ら判断して動ける** |
| **ホスティング** | Anthropicのクラウド | **セルフホスト可能**（完全にコントロール） |

**① 永続メモリ**

Claude Code Channelsは新しいセッションを開くたびに文脈がリセットされる。OpenClawは過去の会話・指示・成果物を全部覚えている。「前にやったあの件の続きやって」が通じる。

**② 自律性**

Claude Code Channelsは「指示 → 応答」の繰り返し。OpenClawはタスクの文脈を理解し、自分で判断して次のアクションを取れる。「やっといて」で動く世界。

**③ セルフホスト**

Claude Code ChannelsはAnthropicのインフラに依存。OpenClawは自分のサーバーで動かせる。データ管理もカスタマイズも全部自分の手の中にある。

### なぜ非エンジニアにとってOpenClawが重要なのか

- **チャットベースで開発できる**（ターミナル不要）
- **永続メモリがあるから積み重ねられる**（毎回ゼロスタートにならない）
- **自律的に動くから細かい指示が不要**
- **セルフホストだから自分の事業にフィットさせられる**

### OpenClawで開発 ── 何が作れるのか

セミナーではOpenClawを使った開発をライブデモで見せた。

- Webサイト・LP（ランディングページ）の構築
- 業務効率化ツール（スプレッドシート連携、通知Bot等）
- データ分析・可視化ダッシュボード
- 自動化スクリプト

**開発ができるようになると、OpenClawの可能性が一気に広がる。** 業務を自動化する仕組みも、集客に使うWebサイトやLPも、自分専用のツールも──「こういうの欲しいな」と思ったものを、自分の手で形にできるようになる。

### スマホからAIに「開発しろ」と指示する

外出先で、スマホのDiscordからメッセージを1つ送る。するとPCでClaude Codeが勝手に動き出して、コードを書いて、GitHub に Push する。

**スマホ片手にカフェでコーヒー飲んでるだけ。**

Claude Code Channels単体だと「賢いAIに毎回ゼロから指示する」。
OpenClaw × Claude Code Channelsだと「あなた専用のAI従業員に一言で仕事を振る」。

### 使いこなすための3つの条件

**OpenClawだけ学んでも意味がない。** 必要なのはこの3つ。

1. **良質なコンテキスト**（何を伝えるか）── 言語化力
2. **AIとの会話術**（どう伝えるか）── 対話力
3. **運用メソッド**（どう回し続けるか）── 継続力

**ノウハウコレクターになるな。学んだら使え、使ったら振り返れ、振り返ったら改善しろ。** その繰り返しが「複利」になる。

### 第4回のまとめ

- **OpenClawとClaude Code Channelsは役割が違う**（永続メモリ・自律性・セルフホスト）
- **非エンジニアにとってOpenClawの開発力は革命的**
- **Claude Code単体よりOpenClaw × Claude Codeの組み合わせが最強**
- **使いこなすには3条件：コンテキスト・会話術・運用メソッド**
- **学ぶことは「複利」。ノウハウコレクターで終わるな**

# 番外編：コスパ最強の使い方 ── 月3,000円以下でAI従業員2人フル稼働

### みんながコスパ悪い4つの理由

**罠①：高いモデルを使いすぎ。** Claude Opus 4.6は最強だけど、日常タスクに毎回使ったら月1〜2万円飛ぶ。
