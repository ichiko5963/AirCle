# コンセプト・ターゲット整理

## セミナーのコンセプト
「チャットでコード0で誰でもエンジニアに！」── OpenClawで"面倒な業務"を全自動化する具体的な方法

### 核心メッセージ
- **開発＝難しい**はもう古い。OpenClawなら**チャットで言うだけで**できちゃう
- プログラミングができなくても、チャットで話しかけるだけで業務システムが作れる
- **なぜ非エンジニアにOpenClawでの開発がオススメか**：参入障壁が1番低い（ターミナル不要・用語知らなくてもOK・ナレッジで業務効率化）
- 実際に作った事例（LINE領収書・Memory System・OrbitX）をデモで見る → 未来（毎日12時業務効率化提案・「やっといて」で開発）→ 実践（①HP簡易 ②請求書管理）
- 経営・マーケ・開発・営業が全部できる経営者が今後の時代に生き残る、という観点で「開発の入口」をOpenClawで

### 戦略的位置づけ（ユニコ会話より）
- Day 4は「開発」フォーカスだが、非エンジニアに向けた実演が中心（60分・Part0〜6）
- Part 3 の事例デモの一部をユニコ氏が担当する場合あり（組織データ可視化・従業員分散管理など）
- 「開発＝難しい」をくつがえし「こんなこともできるの！？」の驚きを積み重ねる回
- Claude Code / Cursor との違い（ターミナル怖くない？→OpenClawがオススメ）を明確に
- 「自分の事業をぶん回す」というスクールコンセプトの直接的な訴求ポイント

## ターゲット層

### プライマリターゲット
- **AIで業務を自動化したいが、プログラミングができない人**
  - 「コードが書けない」ことを理由に自動化を諦めている
  - Claude CodeやCursorは聞いたことがあるが、ターミナルに抵抗がある

- **少人数で事業を回している起業家・事業家**
  - 雑務に時間を取られている（領収書、日報、メール返信etc.）
  - 人を雇う代わりにAIで解決したい
  - 事業のデータを可視化して意思決定を加速したい

### セカンダリターゲット
- **OpenClaw導入済みで自動化の具体例を知りたい人**
  - 第1〜3回からの継続参加者
- **Claude Code / Cursorを使っているが「もっと簡単な方法」を探している人**
  - ターミナル操作は面倒だと感じているエンジニア

## ペインポイント
1. プログラミングができないから自動化は自分には無理だと思っている
2. Claude Code / Cursorは話題だが、ターミナルに抵抗がある
3. 領収書・日報・メール返信などの繰り返し業務に毎日時間を取られている
4. 事業のデータが散らばっていて、全体像が見えない
5. 「AIで自動化したい」が、具体的に何をどう自動化すればいいかわからない

## ソリューション
1. **開発＝そんなことない**を証明し、OpenClawならチャットで言うだけで開発できることを実演で見せる
2. **なぜOpenClawが非エンジニアにオススメか**（ターミナル不要・localhost/Vercel等を即説明できなければOpenClaw向き・ナレッジで業務効率化）を明確に
3. **実際に作った事例**（LINE領収書・OpenClaw Memory System・OrbitX）をデモで公開（ユニコ氏が一部担当する場合あり）
4. **未来**（毎日12時業務効率化提案・「やっといて」で開発が始まる・情報一元管理）を伝える
5. **実践**①HPを簡易的に ②請求書管理システム の流れを体感し、**今日から3ステップ**を持ち帰る

## 期待される成果
- 「開発＝難しい」がくつがえし、「チャットで開発できる」が腑に落ちる
- なぜ非エンジニアにOpenClawでの開発がオススメかが説明できるようになる
- 実際の事例（LINE領収書・Memory System・OrbitX）と実践（HP・請求書管理）の流れがイメージできる
- 今日から始める**3ステップ**（面倒な業務1つ書き出す→OpenClawに「自動化したい」と伝える→1つ「作って」と頼む）を持ち帰る
- Day 5（AI従業員軍団）への期待値が最大化される
